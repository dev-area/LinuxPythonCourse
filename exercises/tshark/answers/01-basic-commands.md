# שלב 1 · פתרונות — פקודות בסיסיות

> חזרה לתרגילים: [../01-basic-commands.md](../01-basic-commands.md)

**1. רשימת ממשקים וזיהוי הממשק של 192.168.0.1**

```bash
tshark -D
ip -brief address | grep 192.168.0.1
```

הממשק שבשורה שמכילה `192.168.0.1/24` הוא הממשק של רשת ה-QEMU (למשל `tap0`). זה ה-`$QNET`.

---

**2. לכידת 5 חבילות בדיוק ל-/tmp/five.pcapng**

```bash
tshark -i "$QNET" -c 5 -w /tmp/five.pcapng
```

`-c 5` עוצר אחרי 5 חבילות, `-w` שומר לקובץ.

---

**3. Capture filter — רק UDP פורט 9001**

```bash
tshark -i "$QNET" -f "udp port 9001"
```

תחביר BPF: `udp port 9001` (בלי נקודות, בלי `==`).

---

**4. Display filter — רק SYN (בלי SYN/ACK)**

```bash
tshark -r /tmp/tcp.pcapng -Y "tcp.flags.syn == 1 && tcp.flags.ack == 0"
```

חבילת SYN ראשונה: ה-SYN דלוק וה-ACK כבוי. ב-SYN/ACK גם ה-ACK דלוק, ולכן היא לא תעבור את המסנן.

---

**5. Delta-time — היכן הכי הרבה זמן בלחיצת היד**

```bash
tshark -r /tmp/tcp.pcapng -t d
```

ברוב המקרים ההפרש הגדול ביותר הוא **בין ה-ACK השלישי של הלקוח לבין שליחת ה-PSH הראשונה** — כי שם מחכים שהאפליקציה (הלקוח) תייצר ותשלח את ה-payload, בעוד שלושת חבילות ה-handshake עצמן קורות ברצף מהיר מאוד זו אחרי זו.

---

**6. מתי `-f` ומתי `-Y`**

- `-f` (capture filter) — **בזמן הלכידה**, כשרוצים לצמצם כמה חבילות בכלל נשמרות: תעבורה כבדה, קובץ גדול, לכידה ארוכה. מה שלא נלכד — אבד לתמיד.
- `-Y` (display filter) — **בניתוח**, על קובץ קיים. לוכדים רחב פעם אחת, ואז מסננים שוב ושוב מזוויות שונות בלי להקליט מחדש.

כלל: צמצום מקור → `-f`; חקירה אחרי ההקלטה → `-Y`.

---

**7. לקוח מול פורט שגוי (9999)**

```bash
python3 ../lab-apps/tcp_client.py 192.168.0.2 9999
tshark -r /tmp/wrong.pcapng -n
```

רואים `SYN` יוצא, ומיד חוזר `RST, ACK` מהשרת (כי אין מאזין על 9999), והלקוח נכשל ב-`ConnectionRefusedError`. זה בדיוק התרחיש שמנותח לעומק ב-[שלב 4.1](../04-troubleshooting.md#41-connection-refused--אין-שרת-שמאזין-tcp-rst).
