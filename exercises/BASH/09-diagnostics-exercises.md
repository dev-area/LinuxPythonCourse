# דף 9 – תרגילי אבחון ופתרונות

➡️ חזרה ל[דף 8 – פקודות אבחון](08-linux-diagnostics.md)

הדף הזה הופך את פקודות האבחון מדף 8 לתרגול מעשי. כל תרגיל הוא **תרחיש תקלה**:
קודם מנסים לאבחן לבד, ואז קוראים את הפתרון.

> ⚠️ הרצה: את התרגילים כדאי לבצע על **מכונת לינוקס אמיתית** (WSL / VM / שרת),
> לא על Git Bash ב‑Windows. חלק מהתרגילים ניתנים לשחזור בפועל (מסומנים 🧪),
> ואחרים הם תרחישי "חשיבה" שבהם מתארים איך היו מאבחנים (מסומנים 💭).

---

## תרגיל 1 🧪 – "No space left on device"

### התרחיש

אפליקציה מפסיקה לכתוב קבצים ומדווחת `No space left on device`, למרות שלדעתכם
יש עוד מקום. אבחנו היכן נגמר השטח ומה תופס אותו.

**לשחזור (בסביבה בטוחה בלבד, למשל תיקיית `/tmp`):**

```bash
mkdir -p /tmp/disktest
# יוצרים קובץ גדול שתופס מקום (200MB)
dd if=/dev/zero of=/tmp/disktest/bigfile bs=1M count=200
```

### המשימה

מצאו: (א) איזו מחיצה הכי מלאה, (ב) איזו תיקייה תופסת הכי הרבה מקום בתוכה.

נסו לבד! 👇

### פתרון

```bash
# 1. איזו מחיצה מלאה? מסתכלים על עמודת Use%
df -h

# 2. איתור "זללני המקום" - התיקיות הגדולות ביותר תחת נתיב מסוים
du -sh /tmp/* 2>/dev/null | sort -rh | head -10

# 3. וריאציה: 20 הקבצים/תיקיות הגדולים ביותר במערכת
du -ah / 2>/dev/null | sort -rh | head -20

# 4. לא לשכוח: לפעמים נגמרים ה-inodes, לא המקום!
df -i
```

**הפתרון:** למצוא את הקובץ הגדול ולמחוק/להעביר אותו:

```bash
rm /tmp/disktest/bigfile
df -h    # לוודא שהשטח התפנה
```

> שימו לב: אם קובץ נמחק אך תהליך עדיין פתוח עליו, השטח לא יתפנה עד שהתהליך ייסגר.
> בודקים זאת עם `lsof | grep deleted`.

## תרגיל 2 🧪 – תהליך שמעמיס את המעבד

### התרחיש

המאוורר של השרת עובד קשה והמערכת איטית. חשד: תהליך "בורח" שצורך 100% CPU.
אתרו אותו והפסיקו אותו.

**לשחזור:**

```bash
# מריצים לולאה אינסופית ברקע שתעמיס ליבה אחת
bash -c 'while true; do :; done' &
echo "started PID $!"
```

### המשימה

מצאו את ה‑PID של התהליך העמוס ביותר, ואז סיימו אותו בצורה מסודרת.

נסו לבד! 👇

### פתרון

```bash
# 1. תצוגה חיה - התהליך העמוס יהיה בראש (q ליציאה)
top

# 2. בשורת פקודה אחת: 5 התהליכים העמוסים ביותר
ps aux --sort=-%cpu | head -6

# 3. בדיקת load average - מעל מספר הליבות = עומס
uptime
nproc
```

**הפתרון:** לסיים את התהליך לפי ה‑PID שמצאנו:

```bash
kill <PID>        # ניסיון ראשון: SIGTERM מסודר
kill -9 <PID>     # רק אם לא נעצר: SIGKILL (כפייה)
```

(ראו דף 3 על סיגנלים – `kill -9` הוא מוצא אחרון.)

## תרגיל 3 🧪 – "Address already in use" (פורט תפוס)

### התרחיש

ניסיתם להפעיל שרת על פורט 8080 וקיבלתם `bind: address already in use`.
מצאו מי כבר תופס את הפורט.

**לשחזור:**

```bash
# מפעילים "מאזין" דמה על פורט 8080 ברקע
nc -l 8080 &
echo "listener PID $!"
```

### המשימה

גלו איזה תהליך (שם ו‑PID) מאזין על פורט 8080.

נסו לבד! 👇

### פתרון

```bash
# שיטה 1: ss (מומלץ, מודרני)
ss -tulpn | grep :8080

# שיטה 2: lsof
lsof -i :8080

# שיטה 3: fuser
fuser 8080/tcp
```

הפלט יראה את שם התהליך ואת ה‑PID. **הפתרון** – לסיים את התהליך או לבחור פורט אחר:

```bash
kill <PID>
```

## תרגיל 4 🧪 – "Permission denied"

### התרחיש

סקריפט מסרב לרוץ עם `Permission denied`, או משתמש לא מצליח לכתוב לקובץ.
אבחנו את בעיית ההרשאות.

**לשחזור:**

```bash
echo '#!/bin/bash' > myscript.sh
echo 'echo "I ran!"' >> myscript.sh
# "שוכחים" לתת הרשאת הרצה ומנסים להריץ:
./myscript.sh        # => Permission denied
```

### המשימה

הבינו למה הסקריפט לא רץ, ותקנו. בנוסף – איך בודקים הרשאות של קובץ נתון?

נסו לבד! 👇

### פתרון

```bash
# 1. בודקים את ההרשאות הנוכחיות (עמודה ראשונה)
ls -l myscript.sh
# -rw-r--r--  => אין x (הרצה)!

# 2. מידע מפורט יותר
stat myscript.sh

# 3. אבחון הרשאות לאורך כל הנתיב (למקרה של בעיה בתיקיית אב)
namei -l ./myscript.sh
```

**הפתרון:** הוספת הרשאת הרצה (ראו דף 1):

```bash
chmod +x myscript.sh
./myscript.sh        # => I ran!
```

> לבעיית בעלות (owner): `chown user:group file`. לבעיית כתיבה: בדקו `w` ב‑`ls -l`.

## תרגיל 5 🧪 – דליפת זיכרון / זיהוי זללן זיכרון

### התרחיש

`free -h` מראה מעט זיכרון פנוי וה‑swap מתמלא. איזה תהליך אשם?

**לשחזור (צורך ~100MB זמנית, ישוחרר כשתלחצו Enter):**

```bash
# תהליך שתופס זיכרון ומחכה
python3 -c "x='A'*100000000; input('holding 100MB, press Enter...')" &
```

### המשימה

מצאו את התהליך שצורך הכי הרבה זיכרון, וכמה הוא תופס.

נסו לבד! 👇

### פתרון

```bash
# 1. תמונת מצב של הזיכרון
free -h
# מסתכלים על available (לא רק free!)

# 2. 10 התהליכים הכי זללני זיכרון (עמודת %MEM / RSS)
ps aux --sort=-%mem | head -11

# 3. תצוגה חיה ממוינת לפי זיכרון
top     # ואז לוחצים Shift+M

# 4. האם מישהו נהרג בגלל חוסר זיכרון בעבר?
dmesg -T | grep -i -E "out of memory|oom-killer"
```

**הפתרון:** לסיים את התהליך הזללן, או להגדיל RAM/swap. במקרה שלנו – לחצו Enter כדי לשחרר.

## תרגיל 6 💭 – אין חיבור לאינטרנט

### התרחיש

משתמש מתלונן "אין אינטרנט". המשימה שלכם: לאבחן **בשיטתיות** היכן השרשרת נשברת,
במקום לנחש.

### המשימה

רשמו את רצף הפקודות לאבחון, מהשכבה המקומית כלפי חוץ, ומה כל כישלון מרמז.

נסו לבד! 👇

### פתרון – אבחון שכבה אחר שכבה

```bash
# 1. יש בכלל כתובת IP לממשק?
ip a
#   אין IP  => בעיית חיבור פיזי / DHCP

# 2. יש route ברירת מחדל (gateway)?
ip route
#   אין default => בעיית ניתוב

# 3. מגיעים לנתב המקומי?
ping -c 3 <gateway-ip>
#   נכשל => בעיה ברשת המקומית / חיווט

# 4. מגיעים לאינטרנט לפי IP (עוקף DNS)?
ping -c 3 8.8.8.8
#   נכשל => בעיית ניתוב/חומת-אש כלפי חוץ

# 5. שמות נפתרים? (אם 4 עבד אבל זה לא → DNS!)
ping -c 3 google.com
nslookup google.com
cat /etc/resolv.conf     # מי שרתי ה-DNS המוגדרים
```

**המסקנה המרכזית:** אם `ping 8.8.8.8` עובד אבל `ping google.com` נכשל –
הבעיה היא **DNS**, לא הקישוריות.

## תרגיל 7 💭 – שירות systemd שנכשל בעלייה

### התרחיש

אחרי אתחול, שירות (למשל `nginx`) לא זמין. אבחנו למה הוא לא עלה.

### המשימה

רשמו כיצד בודקים את מצב השירות, קוראים את סיבת הכישלון, ומאתרים את שורש הבעיה.

נסו לבד! 👇

### פתרון

```bash
# 1. מה מצב השירות? (Active: failed? מה הודעת השגיאה האחרונה?)
systemctl status nginx

# 2. הלוגים המלאים של השירות - כאן תהיה סיבת הכישלון המדויקת
journalctl -u nginx -n 50 --no-pager

# 3. רשימת כל השירותים שנכשלו
systemctl --failed

# 4. לבדוק בעיית קונפיגורציה לפני הפעלה מחדש (ל-nginx יש בדיקה מובנית)
nginx -t

# 5. אחרי תיקון הקונפיג - הפעלה מחדש ואימות
systemctl restart nginx
systemctl is-active nginx
```

**סיבות נפוצות לכישלון:** שגיאת תחביר בקובץ קונפיגורציה, פורט שכבר תפוס
(ראו תרגיל 3), או קובץ/תיקייה חסרים שהשירות צריך.

## תרגיל מסכם 🧪 – סקריפט אבחון אוטומטי

### המשימה

כתבו סקריפט `healthcheck_system.sh` שבודק אוטומטית שלושה דברים ומזהיר אם משהו חורג מסף:

1. שימוש בדיסק מעל 80% → אזהרה.
2. זיכרון פנוי מתחת ל‑10% → אזהרה.
3. load average (דקה אחרונה) מעל מספר הליבות → אזהרה.

הסקריפט מדפיס `OK` או `WARNING` לכל בדיקה ויוצא עם קוד 1 אם הייתה אזהרה.

נסו לבד! 👇

### פתרון

```bash
#!/bin/bash

exit_code=0

echo "===== System Health Check: $(date) ====="

# 1. Disk usage of the root filesystem
disk_used=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
if [ "$disk_used" -gt 80 ]; then
    echo "WARNING: disk usage is ${disk_used}% (> 80%)"
    exit_code=1
else
    echo "OK: disk usage is ${disk_used}%"
fi

# 2. Free memory percentage
mem_total=$(free | awk '/Mem:/ {print $2}')
mem_avail=$(free | awk '/Mem:/ {print $7}')
mem_free_pct=$(( mem_avail * 100 / mem_total ))
if [ "$mem_free_pct" -lt 10 ]; then
    echo "WARNING: only ${mem_free_pct}% memory available (< 10%)"
    exit_code=1
else
    echo "OK: ${mem_free_pct}% memory available"
fi

# 3. Load average (1 min) vs number of cores
load=$(awk '{print $1}' /proc/loadavg)
cores=$(nproc)
# bash has no floats, so compare using awk
if awk -v l="$load" -v c="$cores" 'BEGIN { exit !(l > c) }'; then
    echo "WARNING: load average is $load (> $cores cores)"
    exit_code=1
else
    echo "OK: load average is $load (cores: $cores)"
fi

echo "===== Done ====="
exit "$exit_code"
```

הרצה:

```bash
chmod +x healthcheck_system.sh
./healthcheck_system.sh
echo "Exit code: $?"
```

**מה חדש כאן:** `awk` לחילוץ שדות מפלט של `df`/`free`, חישוב אחוזים ב‑bash,
והשוואת מספרים עשרוניים דרך `awk` (כי bash לא תומך בשברים). משלב את דפים 1, 4 ו‑8.
